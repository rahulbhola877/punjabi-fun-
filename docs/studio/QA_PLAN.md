## Execution contract

- Serialize full tests, build and all software-rendered browsers. A running build/test/browser in another checkout still competes for this machine.
- Use an explicit URL, unique output directory, `BROWSER_PATH=/usr/bin/chromium`, and `SOFTWARE=1` in this environment. `tools/browser.mjs` does not list `/usr/bin/chromium` as an automatic fallback; `pt-lib.mjs` itself imposes a 180 s navigation timeout. Verify the executable exists before running.
- Serve the newly built `dist` with `npm run preview -- --host 127.0.0.1 --port 4173 --strictPort`. Keep it in a managed command session and stop that session afterward. Vite's configured ports alone are insufficient: default dev is 5173 and preview 4173, and many scripts contain historical 4180–4195 defaults.
- Set `SOURCE` to the validated commit/manifest identity. Pass `http://127.0.0.1:4173/` explicitly to every script. `timeout --signal=TERM --kill-after=15s` bounds a command; an outer timeout does not establish a pass. Save stdout/stderr and the exit code. No repeated retries to turn a timing failure green without an explained change.
- A typical shell wrapper is `timeout --signal=TERM --kill-after=15s 420s env BROWSER_PATH=/usr/bin/chromium SOFTWARE=1 SOURCE="$SOURCE" OUT=artifacts/studio/actors node tools/studio-actor-regression.mjs http://127.0.0.1:4173/ > artifacts/studio/actors.log 2>&1`; capture `$?` immediately afterward in the execution record.
- Keep native resolution, actors, and test thresholds. Do not run `UPDATE=1` or edit budget baselines to dismiss a regression. Legacy low-settings checks are explicitly labeled below and do not satisfy full-resolution visual acceptance.

## Remaining acceptance requiring independent observation

**Rooftop actors.** `rooftops.test.ts` alone only validates authored roof spot coordinates. `roofActorOwnership.test.ts` adds causal ownership/support coverage: street tamasha/quarrel must not borrow roof/kite actors; below-roof player/horn/vehicle must not move or bump them; cross-height avoidance must be independent; shift hiding/waking must preserve full post XYZ; legitimate street shift and explicitly scripted procession/roof movement must still work. For a rendered runtime check, select an existing `patang_` flyer, record `__pfs.kites()`, the matching nearby `snapshot().people` XYZ and `resident(id)` brain/trip/away, then trigger a real nearby street event and drive/horn below. Capture before/after at unchanged camera/settings, and observe shift leave/re-entry without a hovering actor. `resident(id)` returns XZ only, so it cannot alone prove roof support height. `snapshot().people` only includes actors within 30 m. No dedicated rooftop browser run was performed by this QA worker; failure to acquire an actual roof actor is NOT RUN, not a pass.

**Touch and interruption.** Exercise main and alternate input owners with real multi-touch pointer IDs: (1) hold joystick, tap Pause with a second finger, release second finger, resume, verify stationary until the original finger lifts and starts a fresh gesture; (2) secondary pointer press/release on stick must not replace/reset the owning pointer; (3) release/cancel/lost capture of another finger must not stop right-thumb look; (4) blur/map/exit while holding inputs clears state and no old movement appears in returned main world; (5) Start/A/B resume consumes the resume action without re-pausing, jumping or attacking, held buttons stay inert until release. The root owns a bounded component/browser regression for these cases; its result must be labeled component versus complete world rendering. `cinematic-controls-smoke` releases both fingers before its pause assertions and does not close this gap.

**Natural main mission.** Play the current home → Bhola → Hello Mobile Zone, Chaura Bazaar → Bhola phone return → repeat delivery → Save → reload/Continue route with ordinary controls. Check reward once (₹200/+10 rep for phone return), stage 999, delivery medal/best, wallet/rep/progress persistence, and playable post-skip input. `tools/playtest.mjs` is the closest existing ordinary-input harness (no teleport/stage setter), but hardcoded routes, old scooter assumptions, opening-cinematic waiting and multi-minute legs need preflight against current source. With `GFX=high`, first-run graphics selection must also be handled before `#title`; otherwise this harness can stall at the chooser. After that preflight correction, a bounded candidate is `timeout --signal=TERM --kill-after=15s 1200s env BROWSER_PATH=/usr/bin/chromium SOFTWARE=1 GFX=high node tools/playtest.mjs http://127.0.0.1:4173/ 1`; it is not a certified current release gate until output/artifacts demonstrate the route. `GFX=high` only avoids the special `gfx=low` override; it does not independently assert saved High settings. Its reports/screenshots must be source-tagged. `playtest2.mjs` requires the phase-1 save and merely logs its reload equality, while catching some failures without a nonzero exit; inspect the semantic report or repair that harness before trusting it. Existing fixture callback/film checks cannot substitute for acquisition, pathfinding, geography, full progression, or a once-only reward assertion.

**Graphics/performance.** `main-route-audit.mjs` samples High 1280×720 main worlds with teleport/fixed steps and real held movement; `production-district-capture.mjs` enters actual alternate worlds but scripts its camera. These can support matched visual/workload comparisons with explicit labels. `district-render-audit.mjs` loads source modules directly and is a development/component diagnostic, not a bundled-production startup test. `alternate-cost-profile.mjs` instead enters the production worlds and uses CDP closure inspection plus fixed-step rendered/update-only phases; label its instrumentation and rendering suppression. `performance-mode-smoke.mjs` requires `window.__game`, which `src/main.ts` assigns only in DEV, and targets a removed performance shortcut; do not run it blindly as a current production gate. `foundation-physics-smoke.mjs` has production-compatible physics checks but its optional PCM/audio tap returns unavailable without DEV `__game`; a production pass does not include that audio-tap coverage. Production `?probe` is available because `Game.init()` installs it based on the query, and it exposes mutating fixture APIs despite older “read-only” comments. The new actor script asserts `__game` is absent and uses only production scene/probe APIs.

Software rendering is useful for errors, workload counts, resolution, deterministic state and captured pixels. It does not establish phone/PC GPU FPS, touch latency on hardware, battery/thermal behavior, audible mix, Safari/Firefox support, or sustained memory health. Full-resolution screenshots are necessary for art claims but insufficient for runtime performance. Record these limits, any failed budget rows, incomplete natural mission evidence and missing rooftop runtime evidence in the final ledger rather than claiming a whole-game QA pass.
